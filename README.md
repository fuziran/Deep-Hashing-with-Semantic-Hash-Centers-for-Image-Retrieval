# Deep Hashing with Semantic Hash Centers for Image Retrieval

## Overview
This repository is the PyTorch implementation of ACM TOIS 2025 (CCF A) paper: "Deep Hashing with Semantic Hash Centers for Image Retrieval".

![structure](./save_figures/structure.png)

**SHC** is a three-stage framework designed to generate hash codes that accurately preserve semantic information, significantly enhancing large-scale image retrieval performance.

### Core Workflow
<ol>
  <li><strong>Semantic Similarity Detection</strong>: Construct a classification network to identify semantic relationships between classes, and adopt a data-dependent similarity calculation method that flexibly adapts to different data distribution characteristics.</li>
  <li><strong>Semantic Hash Center Generation</strong>: Propose a new optimization algorithm that maintains the semantic relevance of hash centers while ensuring a minimum distance between them through distance constraints. This effectively addresses the issue of degraded retrieval performance caused by excessively close hash centers.</li>
  <li><strong>Deep Hashing Network Training</strong>: Train a deep hashing network based on the generated semantic hash centers to efficiently convert images into binary hash codes.</li>
</ol>


### Experimental Results
Experiments on large-scale image retrieval across several public datasets demonstrate that the hash codes generated by SHC have stronger discriminative power, significantly improving retrieval accuracy and efficiency.​
Feel free to explore the implementation details in the code repository or conduct secondary development based on this framework!

## Train

### Audited B0 baseline (CIFAR-100)

The main B0 protocol reserves 10 images per class from the 10,000-image
training pool for validation. The 5,000-image query set is used only once for
the final evaluation. Run the CPU-only unit tests before using the GPU:

```bash
python3 -m unittest discover -s tests -v
```

Run a one-epoch smoke test first:

```bash
export CUBLAS_WORKSPACE_CONFIG=:4096:8
python3 run.py --dataset cifar-100-new-seg \
  --root ./data/cifar-100-python \
  --num-classes 100 --code-length 32 --seed 60 \
  --classify-epoch 1 --epoch 1 --test-map 1 \
  --batch-size 64 --num-workers 4 --topK -1 100 1000
```

For the reported B0 result, restore both epoch counts to 300. Splits, cache
metadata, the selected checkpoint, all three mAP values, per-query AP and
binary codes are written under `save/`. Use `--stage similarity` or
`--stage centers` to stop after a diagnostic stage, and use
`--force-recompute` only when intentionally replacing a matching cache.

## I2-R：创新一＋比特级中心监督（B2R）

分支 `update-reliable-relation-bit-supervision` 新增 `--variant b2r`。`b0`、`b1`、原 `b2` 保留；`b2r` 使用固定的 B1 关系矩阵和最终中心，以有界加权 BCE 替换均匀 BCE，保留原量化项，不叠加中心竞争损失。哈希网络从配对初始化独立训练，不加载 B1/B2 最佳网络续训。方案是否提高检索指标仍需正式训练验证。

默认参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--i2r-rho` | 0.25 | 最大比特重加权强度，与原 comp-weight 无可比性 |
| `--i2r-stats-start` | 16 | 开始累计训练前向的连续中心偏离 |
| `--i2r-warmup` | 20 | 本轮结束后冻结统计；此前保持 B1 损失 |
| `--i2r-ramp-end` | 40 | 第21至40轮将 rho 从0线性升至最大值 |

几何权重 A 按异类关系权重与中心区分位数量计算；连续偏离 e 按训练样本出现次数累计，不平均批次均值。每类风险 v 为 A×e 经类内最大值归一化，权重 w=(1+rho×v)/mean_bits(1+rho×v)。每类平均权重为1；默认 rho 下权重在[0.8,1.25]内。重复异类中心、缺失类别统计和非有限输入将报错。统计使用 detach 后的 CPU float64，不新增图像前向或随机采样；会增加少量设备同步和统计开销。权重统计不是独立测试误差或校准置信度。

冻结产物与 B2 一样通过 `--parent-b1-config`、`--similarity-cache`、`--center-cache` 显式传入，并要求 `--paired-stage-seeds`。共同配置（包括总轮数）必须匹配 B1；不能仅将 epoch 改为1做短程试跑。正确性检查使用不依赖数据的测试：

```bash
python -m unittest discover -s tests -v
```

以下为报告记录的远程项目 `/mnt/d/fzr/SHC` 下首个筛选实验命令。执行前应将本分支代码同步至该机器，并确认三个父级产物路径存在。命令不会由文档自动执行。

```bash
cd /mnt/d/fzr/SHC
mkdir -p logs
stamp=$(date +%Y%m%d_%H%M%S)
nohup python -u run.py \
  --variant b2r --paired-stage-seeds --skip-query \
  --dataset cifar-100-new-seg --root ./data/cifar-100-python \
  --num-classes 100 --code-length 32 --seed 60 \
  --classify-epoch 300 --epoch 300 --test-map 5 \
  --lr 7e-5 --batch-size 64 --num-workers 4 --gpu 0 \
  --topK -1 100 1000 \
  --parent-b1-config ./save_i1/runs/cifar-100-new-seg_B1_32bit_seed60_a13a73393ff8/config.json \
  --similarity-cache ./save_i1/SimilarityMatrix/cifar-100-new-seg_82618139bb9c.pt \
  --center-cache ./save_i1/HashCenters/cifar-100-new-seg_SHC_9b87e583acee.pt \
  --i2r-rho 0.25 --i2r-stats-start 16 --i2r-warmup 20 --i2r-ramp-end 40 \
  --output-dir "./save_b2r_${stamp}" \
  > "logs/b2r_32bit_seed60_${stamp}.log" 2>&1 &
```

运行目录标识包含 I2-R 参数、统计版本、源码摘要及父级内容摘要。第20轮结束时新增：

- `i2r_statistics.pt`：A、偏离累计和、每类样本次数、e、v、冻结状态、最大 rho 下的 w，以及内容摘要。
- `i2r_diagnostics.json`：上述分布的分位数、均值、标准差与内容摘要。
- `config.json`：补记统计文件路径及内容 SHA256；运行前尚未产生的统计摘要不参与初始目录名。

训练历史新增 `loss_center_uniform` 和 `i2r_rho`；`loss_center` 是实际用于训练的加权 BCE（关闭权重时为原 BCE），`loss_comp` 和 `comp_weight` 均为0。原 `--comp-*` 默认字段可能仍出现在配置中，但 B2R 不启用竞争模块。

先检查前20轮与配对 B1 的损失和验证是否对齐，再检查 A/v/w 是否有实际选择性。按验证 mAP@ALL 选模，与报告中的 B1=0.55422 比较，并同时报告另外两项验证指标。首轮继续跳过 query；冻结方案后再进行最终 query 评价，不根据 query 调参。未完成真实训练前，不声称 I2-R 有效或已经形成递进提升。

## B2-M：语义关系与中心距离约束的混合正则

新增 `--variant b2m`，组成是冻结 B1 加混合图辅助监督。
`--mix-mode semantic` 为 I2-M；`--mix-mode plain` 为普通中心 Mixup 对照。
尚未运行真实训练或评价，代码实现不代表指标提升。

- 原图仍用 B1 的 BCE 和 1e-4 量化项；混合图只用 `BCEWithLogits(2*z, soft_target)`。
- semantic：先按类别均匀/批内语义 top5 各一半选异类，再在该类均匀选伙伴；同分按类别 ID 排序。
- plain：在批内全部异类样本中均匀选伙伴，不使用语义偏好或距离上限。
- 两组均采样伙伴占比 beta0~Uniform[0,0.5)。semantic 取 beta=min(beta0, budget/d_H)，默认 budget=码长/16，32 bit 时为2；plain 使用 beta0。
- 混合图和软中心使用同一个 beta。异类中心重复会报错；批次没有异类时跳过混合分支。
- 默认辅助权重：前20轮为0，第21–40轮升至0.1，此后固定。为0时不采样、不额外前向。
- 原图反传后再混合图反传，最后只调用一次 optimizer.step。混合分支仅冻结 BN 的运行统计，保留仿射参数梯度。
- 冻结关系及中心沿用父 B1 的配置、内容摘要、缓存元数据校验。哈希网络从配对初始化独立训练，不读取父 B1 最佳网络权重。
- semantic/plain 使用同一辅助权重日程、BN规则和额外前向次数。约1.93倍图像处理量，实际耗时以日志为准；推理不变。

### 产物和判断

- `config.json`：完整参数、mix版本、独立采样种子、BN规则、父级来源及源码摘要。
- `training_history.json`：原图BCE/量化、混合BCE/目标熵/KL、权重、每轮训练耗时和验证指标；B2-M逐轮落盘。分项损失按批次平均，无有效混合样本的批次记0；配对分布按有效样本统计。
- `mix_diagnostics/epoch_NNN.json`：有效配对数、完整类别对计数、beta/中心距离/关系值的均值与分位数、上限触发率。未启用或无有效配对时不伪造分布。
- 每轮第一个批次有有效混合样本时记录原图梯度范数及加权混合梯度增量范数，名称以 `sampled_` 开头；这是抽样值，不是整轮平均。
- `mix_sampler_state.pt`：最近一轮结束的独立采样器状态，模块支持 `load_state_dict`。它不是完整训练断点；当前没有新增恢复训练命令，恢复整个训练还需网络、优化器、调度器及其他随机状态。
- `best_model_state.pt` / `metrics.json`：仍按验证 mAP@ALL 选同一个模型；传入 `--skip-query` 时不做最终查询评价。

首轮开发门槛：同一选中模型的验证 ALL > 0.5542233697802248，@100 >= 0.65456859，@1000 >= 0.63411706（后两值为报告保存精度）。
前20轮与配对B1对照属于远程运行后核验项，本地合成测试不能替代该验证。
混合BCE即使完美拟合也有目标熵下限，应结合KL而非仅看总损失；总损失不能直接与B1比较。
开发阶段使用 `--skip-query`，冻结配置后才评价query，不将单种子结果描述为稳定递进提升。
